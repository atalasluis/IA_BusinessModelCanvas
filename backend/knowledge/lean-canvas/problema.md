# Lean Canvas — Problema

## Propósito

El bloque Problema identifica los problemas que el segmento de clientes seleccionado necesita resolver. En Running Lean, este bloque debe abordarse antes de desarrollar una solución detallada.

## Qué debe contener

El canvas debe concentrarse inicialmente en los principales problemas del segmento seleccionado. El libro propone enumerar hasta tres problemas principales y estudiar cómo los clientes resuelven actualmente esas situaciones.

Un problema útil para el canvas debe describir una necesidad, dificultad, frustración, limitación o resultado no deseado del cliente. No debe ser simplemente una característica que la empresa quiere construir.

## Problema frente a solución

Debe evitarse transformar prematuramente el problema en una solución.

Ejemplo conceptual:

- Problema: el cliente pierde tiempo al realizar una tarea repetitiva.
- Solución prematura: crear una aplicación que automatice esa tarea.

La primera afirmación describe la situación del cliente. La segunda ya supone una implementación concreta.

## Alternativas existentes

Una parte importante del análisis consiste en documentar cómo los early adopters resuelven actualmente el problema.

Las alternativas pueden ser:

- productos existentes;
- servicios;
- procesos manuales;
- hojas de cálculo;
- herramientas gratuitas;
- proveedores;
- contratar a otra persona;
- no hacer nada;
- combinar varias soluciones.

Las alternativas existentes ayudan a comprender qué está utilizando realmente el cliente y contra qué tendrá que competir una nueva propuesta.

## Problema que merece la pena solucionar

Running Lean propone evaluar si existe un problema suficientemente importante antes de invertir grandes cantidades de tiempo en construir una solución.

Tres preguntas orientadoras son:

1. ¿El cliente quiere resolverlo?
2. ¿Existe disposición a pagar o existe alguien que pagará por resolverlo?
3. ¿Es factible resolverlo?

Estas preguntas ayudan a separar un problema interesante de un problema que puede sostener un modelo de negocio.

## Descubrimiento del problema

Las entrevistas deben buscar comprender la experiencia real del cliente, no pedirle simplemente que diseñe el producto.

Es especialmente útil preguntar por:

- qué ocurrió recientemente;
- cómo realiza actualmente la tarea;
- qué alternativa utiliza;
- qué dificultades encuentra;
- con qué frecuencia aparece el problema;
- qué consecuencias produce;
- qué ha intentado hacer para solucionarlo;
- cuánto esfuerzo o recursos utiliza actualmente.

## Early adopters

El segmento inicial no debería ser "todo el mercado". Debe buscarse el grupo que experimente el problema con mayor intensidad y tenga mayor motivación para probar una alternativa.

A medida que se realizan entrevistas, el perfil del early adopter puede hacerse más específico.

## Evidencia

Un problema expresado en el canvas debe diferenciarse de un hecho comprobado.

Usar:

- **Hipótesis** cuando todavía debe validarse.
- **Evidencia** cuando existe información verificable.
- **Observación cualitativa** cuando proviene de entrevistas u observaciones.
- **Dato cuantitativo** cuando existe una medición con fuente identificable.

Nunca convertir una suposición en una estadística.

## Criterios de calidad para el RAG

Al generar este bloque:

- priorizar problemas concretos;
- relacionarlos con un segmento;
- distinguir problema de solución;
- considerar alternativas existentes;
- identificar qué necesita validarse;
- no inventar porcentajes, tamaños de mercado o frecuencia;
- señalar cuando la evidencia sea insuficiente.
