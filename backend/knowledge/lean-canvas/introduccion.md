# Lean Canvas — Introducción metodológica

## Propósito

Este conjunto de conocimiento resume y adapta los conceptos de *Running Lean: Cómo iterar de un plan A a un plan que funcione*, de Ash Maurya, para utilizarlos como contexto de recuperación (RAG) en un sistema que genera Lean Canvas.

Lean Canvas se presenta en el libro como una herramienta de una sola página para documentar el plan inicial de un modelo de negocio, identificar sus elementos de mayor riesgo y utilizarlo como punto de partida para experimentar y aprender.

## Principios de Running Lean

La metodología se organiza alrededor de tres acciones:

1. Documentar el plan A.
2. Identificar los elementos de riesgo del plan.
3. Poner a prueba el plan de manera sistemática.

El objetivo no es demostrar que el primer modelo es correcto, sino iterar hacia un modelo que funcione antes de agotar los recursos disponibles.

## El Lean Canvas como hipótesis

Los elementos del canvas deben tratarse como hipótesis y no como hechos definitivos. Una idea inicial suele contener supuestos no comprobados sobre clientes, problemas, solución, canales y viabilidad económica.

Por ello, el canvas debe poder cambiar cuando aparece nueva evidencia.

Una respuesta como "no lo sé" puede ser válida cuando todavía no existe evidencia suficiente. Un bloque incompleto puede señalar un riesgo que necesita ser investigado.

## Enfoque centrado en el cliente

El libro recomienda comenzar desde la pareja:

- problema;
- segmento de clientes.

La solución debe definirse después de comprender mejor el problema. El modelo debe centrarse en aquello que el cliente necesita resolver y en las alternativas que utiliza actualmente.

## Hipótesis falsables

Una buena hipótesis debe poder ponerse a prueba. Para ello debe describir una acción concreta y un resultado esperado que pueda observarse o medirse.

Ejemplo de estructura:

> Acción específica y repetible → resultado esperado y medible.

Esto evita afirmaciones vagas como "a los clientes les gustará el producto".

## Validación e iteración

Running Lean distingue varias etapas de aprendizaje:

- comprender el problema;
- definir una solución;
- validar cualitativamente;
- verificar cuantitativamente.

La lógica general es crear algo para probar una hipótesis, medir la respuesta y aprender de los resultados.

## Uso dentro del RAG

Cuando este documento sea recuperado, el sistema debe recordar que:

- el Lean Canvas es una fotografía del conocimiento actual;
- los bloques representan hipótesis;
- no debe inventarse evidencia;
- los problemas deben tener prioridad sobre las soluciones;
- la información debe poder revisarse y actualizarse;
- la validación con clientes y la evidencia observable son fundamentales.
