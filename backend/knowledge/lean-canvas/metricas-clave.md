# Lean Canvas — Métricas clave

## Propósito

Las métricas clave permiten evaluar si el modelo está avanzando y detectar puntos importantes del ciclo de vida del cliente.

Running Lean recomienda utilizar métricas que ayuden a tomar decisiones y no únicamente números que parezcan positivos.

## Métricas accionables

Una métrica útil debe relacionarse con una acción o comportamiento del usuario y permitir aprender algo.

Debe evitarse depender únicamente de métricas de vanidad que puedan aumentar sin demostrar que el modelo funciona.

## Marco de métricas para piratas

Running Lean utiliza el marco conocido como AARRR o "métricas para piratas":

### Adquisición

Momento en que un visitante se convierte en un cliente potencial interesado.

Ejemplos:

- visita relevante;
- registro;
- contacto;
- solicitud de información.

### Activación

Momento en que el usuario tiene una primera experiencia satisfactoria con el producto.

Debe comprobarse que la experiencia corresponde con la promesa de la propuesta de valor.

### Retención

Mide el uso repetido o compromiso con el producto.

Puede observarse mediante:

- usuarios que regresan;
- frecuencia de uso;
- renovación;
- repetición de compra.

### Ventas

Mide los eventos que conducen al pago.

Ejemplos:

- compra;
- suscripción;
- renovación;
- contratación.

### Recomendación

Mide cuándo clientes satisfechos ayudan a atraer nuevos clientes.

Puede incluir:

- referencias;
- invitaciones;
- compartidos;
- mecanismos específicos de recomendación.

## Métricas relacionadas con hipótesis

Cada métrica debe responder a una pregunta del modelo.

Ejemplo:

Hipótesis: "El canal X generará nuevos registros."

Métrica: número de registros atribuibles al canal X.

Hipótesis: "Los usuarios encontrarán valor después del primer uso."

Métrica: porcentaje que vuelve a utilizar el producto dentro del periodo definido.

## Métricas cualitativas y cuantitativas

Antes del ajuste producto/mercado, la incertidumbre es alta. En esa fase las entrevistas y otras formas de aprendizaje cualitativo pueden proporcionar información valiosa.

Después se pueden utilizar mediciones cuantitativas para verificar patrones a mayor escala.

No se debe utilizar una gran cantidad de datos como sustituto de comprender el problema.

## Ajuste producto/mercado

Las métricas deben ayudar a saber si se ha creado algo que la gente quiere.

Algunas señales pueden estar relacionadas con:

- adquisición;
- activación;
- retención;
- ingresos;
- recomendación.

La métrica concreta debe adaptarse al modelo.

## Datos y fuentes

Si el sistema utiliza estadísticas externas, cada cifra debe conservar:

- valor;
- unidad;
- población;
- periodo;
- ubicación cuando corresponda;
- definición;
- fuente.

Si no existe una fuente verificable, el sistema debe presentar la cifra como hipótesis o indicar que no hay evidencia suficiente.

## Criterios de calidad para el RAG

Al generar este bloque:

- escoger pocas métricas relevantes;
- relacionarlas con comportamientos concretos;
- evitar métricas de vanidad;
- indicar qué hipótesis mide cada métrica;
- diferenciar cualitativo de cuantitativo;
- no inventar resultados;
- conservar las fuentes de datos externos.
