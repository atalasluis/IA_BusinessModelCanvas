# Lean Canvas — Segmentos de clientes

## Propósito

Este bloque identifica quién tiene el problema y quién puede convertirse en usuario, cliente o comprador.

Running Lean concede especial importancia a la pareja problema-segmento de clientes porque un cambio en el segmento puede modificar prácticamente todo el modelo de negocio.

## No utilizar "todo el mundo"

Un segmento demasiado amplio dificulta la validación. El enfoque inicial debe ser suficientemente concreto para poder identificar personas reales con características y problemas relacionados.

Ejemplos de dimensiones útiles:

- tipo de cliente;
- contexto de uso;
- comportamiento;
- situación que desencadena la necesidad;
- características demográficas cuando sean relevantes;
- características profesionales;
- tamaño o tipo de organización;
- frecuencia con que aparece el problema.

## Usuario, cliente y comprador

No siempre son la misma persona.

Puede existir:

- usuario: utiliza el producto;
- cliente: mantiene la relación comercial;
- comprador: toma la decisión de pago;
- beneficiario: recibe el beneficio.

El canvas debe aclarar estas diferencias cuando sean relevantes para el modelo.

## Early adopters

El early adopter es el segmento inicial que presenta una necesidad más intensa y está más dispuesto a probar una solución nueva.

No debe confundirse con el usuario promedio del mercado futuro.

Una estrategia útil es comenzar con un grupo pequeño que tenga:

- un problema claramente reconocible;
- suficiente motivación para solucionarlo;
- comportamiento observable;
- alternativas actuales identificables;
- posibilidad real de ser contactado.

## Dividir segmentos

Si un segmento resulta demasiado amplio, puede dividirse en grupos más específicos.

También puede ser útil crear canvas alternativos para diferentes segmentos y compararlos.

El libro sugiere priorizar segmentos considerando, entre otros factores:

1. nivel de necesidad del cliente;
2. facilidad para llegar al segmento;
3. precio y margen potencial;
4. volumen de mercado;
5. viabilidad de la solución.

## Mercado inicial y mercado futuro

El segmento inicial no tiene que representar inmediatamente todo el mercado disponible.

Primero interesa encontrar un segmento que permita aprender y validar el modelo. Después puede analizarse la expansión.

## Evidencia

El segmento debe basarse en el contexto proporcionado y, cuando exista, en evidencia.

No asumir que una categoría demográfica implica automáticamente una necesidad.

Ejemplo incorrecto:

"Los estudiantes universitarios necesitan esta aplicación."

Mejor:

"Estudiantes universitarios que experimentan específicamente el problema X en el contexto Y."

La segunda formulación permite plantear una hipótesis comprobable.

## Criterios de calidad para el RAG

Al generar este bloque:

- identificar un segmento concreto;
- distinguir usuario, cliente y comprador cuando corresponda;
- priorizar early adopters;
- explicar por qué ese segmento es relevante;
- evitar segmentos excesivamente amplios;
- señalar hipótesis que requieren validación;
- no inventar tamaños de mercado.
